# 图纸生成提速与保真渐变设计

日期：2026-11-09

## 目标与约束

生成所有尺寸的图纸都有等待感，尺寸越大越慢；用户通常关闭「去除背景」。平滑渐变出现零散异色格，色带交界突兀，但改进必须以尽可能还原原图为前提。分两个可独立交付、独立验证的阶段：第一阶段只提速，逐格色号及 EMPTY **完全不变**；第二阶段允许在明确平滑且修改更符合原图的区域调整少量色号。默认库存、H1 与固定透明格、镜像、保存 PNG 等现有规则不变。

## 阶段一：结果完全一致的性能优化

- 建立同一运行环境的基线与复测：使用既有 100×100/221 色 benchmark，并增加代表常用「我的颜色」的 48×48、较大 150×150/200×200 样例；统一输入、种子、预处理、调色板、迭代次数和构建配置。重复运行取中位数，分别记录预处理（图片归一化／缩图）、重要性图、轮廓检测、颜色优化（含分格迭代与颜色匹配）、去噪／渐变修正、alpha 分类、持久化与缩略图耗时；优先针对默认「去除背景」关闭的路径，额外测开启路径确保不退化。
- 找到热点后优先移除纯重复计算／无关分配：例如候选豆色的 Lab/HSL 属性在相同调色板和迭代中重复计算、像素细分候选容器／最大 importance／不变量在循环中重复建立等；前提是**严格保持候选顺序、浮点运算顺序与 tie-break 行为**。不调整 `iterations`、阈值、缩图像素数、重要性权重、颜色距离公式或其它影响图纸的参数。分阶段优化并用旧实现的固定输入快照或对照运行逐格验证相等，包括 12/24/48/221 色、渐变、轮廓、透明空格/H1、横竖图片和不同尺寸。若一次改动导致任何格色号不同，应回退或另列入阶段二讨论。
- 性能验收以真实测量为准，不预设必须达到某个倍数；报告每个尺寸前后中位数、热点分布及差异，确保加速收益不是测试噪声。构建与 UI 生成流程保持可取消性和错误处理现状，不为单一 benchmark 牺牲正常图纸。

## 阶段二：原图优先的局部渐变改善

- 使用同一组图片和库存分别生成优化前后图纸，覆盖平滑连续渐变、真实纹理、小花纹、深色轮廓、明暗交界、半透明边界与 H1 孔洞；记录每格的原图统计 Lab、局部邻域变化、轮廓证据、原匹配色及候选色与原图距离。以主观并排对比配合客观指标（每格色差的均值/高分位、离群异色格数、明显色带跳变数），避免单一“平滑度”分数导致丢细节。
- 首选**受约束后处理实验**：只在原图本身平滑、非轮廓且邻域有连贯趋势时，考虑将零散异色格替换为本次调色板中与邻域更连贯的颜色；可以让少量格子相对原图的 Lab 色差小幅增加，但必须设定并公开单格增加上限，逐格记录旧新色差、总图均值及高分位变化，原图还原度明显恶化时拒绝候选。色带硬跳变若涉及成片的最优颜色分区，不强行磨平；保护真实纹理、花纹、彩色/深色边缘。限定替换色来自当前库存，不造新色；明确的透明/EMPTY/H1 固定格和其边界邻格不修改，Vision 去背景产生的空格不填回。实验结果经用户看图认可前绝不接入默认生成。
- 对比采取「是否改」「改到哪里」逐格可解释；如果特定图像不存在能同时减轻斑驳又维持原图色差的候选，就维持原图纸，不承诺所有渐变都变成连续过渡。阶段二另设可视化验收（原图＋旧图＋新图及局部放大），用户看样图认可后再把画质改动并入默认生成链路。阶段二的变化不回算为阶段一的无损加速收益。

## 测试与交付

- 第一阶段：逐格快照对照测试、基准中位数、BeadCore/BeadPersistence 全量测试、iOS 模拟器生成与重新生成主流程；报告绝对耗时、相对变化和采样条件。
- 第二阶段：合成平滑梯度／有意纹理／轮廓及真实案例对比；检查局部改色仍在库存中，H1/EMPTY 与色号图例一致，历史图纸不受重新生成以外的操作影响；性能不应明显倒退，测量后给出真实结果。
- 当前规格描述行为和验收边界，不将未经 profiling 的猜测写成已确认瓶颈；实施时先做阶段一，再独立规划和验收阶段二。
