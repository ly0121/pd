# 拼豆图纸生成 iOS App 设计文档

日期：2026-09-28

## 背景与目标

做一个 iOS 原生 App，让用户把照片（相册/拍照）自动转换成可实际拼制的拼豆（潘娜 MARD 色卡）图纸，并支持手动修图、颜色用量统计、导出成品图纸。纯本地处理，无网络依赖。

市场调研发现，现有工具（BeadMapper、Pixel-Beads、Pixelbead、MakeBead、Beads Creator、Perlypop 等）普遍采用"区域平均色 + 最近色匹配"的简单流程，对复杂背景/人像/宠物照片容易产生孤立噪点，且转换后主体的"身份特征"（如宠物的五官、花纹）容易被平均掉，导致成品"看起来不像本来的样子"。参考论文 *Pixelated Image Abstraction* (Gerstner et al., 2012, 简称 PIA) 的思路，本设计采用更接近论文方法的算法链路，以在保持工程可行性的前提下，尽量保留主体的关键特征。

## 技术栈

- SwiftUI + SwiftData（iOS 17+）
- Vision 框架（主体检测/显著性检测，用于生成重要性权重图）
- Accelerate / vImage（图像数值计算，保证大网格下的性能）
- 纯本地处理，无后端

## 核心算法：图片 → 拼豆像素图

传统"区域平均色 + 最近色匹配"是一条低通滤波链：平均、合并、平滑、清理，每一步单独看都合理，但叠加后会把主体的身份特征（五官、花纹、轮廓细节）当作噪声滤掉。本设计采用以下流水线：

1. **重要性权重图生成**
   用 Vision 框架对原图做主体检测/显著性分析（人物分割、动物身体检测、基于注意力的显著性检测，按图片内容自动选择或组合），生成一张与原图等大的灰度权重图：主体轮廓、面部/五官区域权重高，背景权重低。
   - 检测失败或无法识别主体时，权重图退化为均匀权重，等价于跳过这一步，不影响后续流程可用性。

2. **结构增强前置**
   在降采样/分割之前，对高权重区域做适度的边缘增强/对比度拉伸，确保关键结构线不会在被压缩到格子分辨率之前被平均糊掉。

3. **SLIC 超像素分割（改进版）**
   每个输出格子对应原图中一块经过优化的不规则区域（superpixel），而非机械的方格切割。分割过程引入重要性权重图：高权重区域的 superpixel 更小更密，从而在有限的格子总数下，向主体细节（如眼睛、鼻子、耳缘、标志性花纹）分配更多"格子资源"；背景等低权重区域的 superpixel 更大更稀疏。

4. **调色板联合优化（迭代收敛）**
   区域划分（superpixel 归属）与颜色分配（该区域最终对应哪个 MARD 色号）不是先后两个独立步骤，而是迭代循环：
   - 给定当前区域划分，为每个区域挑选最优 MARD 色号（Lab 色彩空间距离）
   - 给定当前颜色分配，重新优化区域边界，使同色区域更聚合、边界更贴合实际色彩过渡
   - 重复直到收敛或达到最大迭代次数
   这样格子颜色始终由"实际会被使用的 MARD 色号"参与区域决策，避免为一个不存在于色卡中的中间色去优化边界。

5. **孤立噪点清理**
   作为收尾步骤，扫描网格，将总数 ≤2 且被其他单一颜色完全包围的孤立色块，替换为周围主色。此规则不会误伤大范围颜色交替的图案（如棋盘格），因为交替色块的总颜色数量通常远大于 2。

**性能与交互**：SLIC 分割 + 迭代优化的计算量明显高于简单区域平均，在 Accelerate/vImage 加速下预计仍需数百毫秒到数秒（视画布格数），因此生成过程在后台线程执行，UI 需显示处理进度，不能假设瞬时完成。

**中间产物**：重要性权重图、superpixel 分割结果等均为生成时的临时计算产物，不持久化存储；重新生成时会完整重新计算。

## 色卡数据

内置 **MARD 潘娜标准 221 色**（A~M 共 9 个系列：A26/B32/C29/D26/E24/F25/G21/H23/M15），均为常规不透明色，适合算法匹配，也是市场上最容易买到的套装。不包含 P/Q/R/T/Y/ZG 等特殊效果色（温变、夜光、光变、半透明等）——这些颜色的显色受光照/温度影响，HEX 值仅为近似参考，且各数据源统计口径不一致，用于算法匹配价值有限。

颜色匹配逻辑与色卡数据解耦，为未来扩展其他色卡（Perler/Hama/291 色等）留出空间，但本版本不做多色卡切换 UI。

## 功能模块与交互流程

### 页面结构

1. **项目列表页**：展示所有已保存的拼豆项目（缩略图 + 名称 + 最后编辑时间），支持新建/删除项目。
2. **新建项目流程**：
   - 选择图片来源（相册/拍照）
   - 选择画布格数（预设列表：16×16、24×24、36×36 … 直至 200×200，以及自定义），交互参考珊瑚粉圆角卡片风格的网格选择弹层
   - 非方形图片按选定画布比例做居中裁剪，裁剪框可拖动调整取景范围，不做拉伸变形
   - 自动生成图纸（跑上述算法流水线，显示处理进度）
   - 进入编辑器
3. **图纸编辑器**（核心页面）：
   - 网格画布：显示每格对应的 MARD 色号色块，支持缩放/平移
   - 色板列表：显示当前图纸用到的颜色 + 每色用量，点击某色可高亮所有该色格子（照顾色盲/色弱用户单独查看某颜色分布的需求）
   - 手动修图工具：画笔（选定目标色后涂色）、橡皮（清空格子）、吸色（取已有格子颜色）、撤销/重做
   - 参数面板：可重新调整画布格数并重新生成；若已有手动修改，重新生成前需二次确认（会丢弃手动修改）
4. **导出/分享**：生成带网格线、行列坐标、颜色图例的成品图纸图片，可保存到相册或系统分享。

### 数据流

原图（存于项目内，供重新生成使用）→ 算法流水线（权重图/SLIC/联合优化均为临时计算，不持久化）→ 颜色索引网格（核心持久化数据，二维数组，每格存 MARD 色号）→ 编辑器读写该网格 → 导出时渲染成图片。

颜色用量统计实时根据当前网格计算，供编辑器色板和导出图例使用。

## 视觉风格

延续用户提供的参考截图风格：珊瑚粉圆角卡片、圆角矩形按钮、粉白配色、清晰的网格选择弹层。整体轻量、可爱、手工风，符合拼豆手工艺品类调性。

## 数据模型（SwiftData）

- `BeadProject`：id、name、创建/修改时间、原图（Data）、画布宽高、颜色网格（二维 MARD 色号数组，序列化存储）、缩略图。
- `MardColor`：内置常量数据（色号、HEX/RGB、系列），非持久化模型，随 App 打包。
- 保存时机：自动保存（每次手动修图操作后 debounce 落盘），无需用户手动点"保存"。

## 边界情况处理

- 图片非方形：居中裁剪（可调整取景范围），不拉伸变形。
- 画布格数很大（如 200×200）配合原图分辨率很小：仍正常跑算法，允许结果模糊，不做额外限制。
- Vision 检测失败/无可识别主体：权重图退化为均匀权重，不影响流程可用性。
- 孤立噪点清理误伤大范围交替图案：清理规则限定"总数 ≤2 且被单一颜色完全包围"，规避棋盘格类图案。

## 测试策略

- 单元测试覆盖核心算法：重要性权重图生成（含退化情形）、SLIC 分割、调色板联合优化收敛性、Lab 色差最近色匹配、孤立噪点清理——用已知输入验证输出网格符合预期。
- 手动验证关键路径：导入图片 → 生成 → 手动改色 → 撤销 → 导出，在模拟器/真机上跑通。
- 由于本设计的差异化价值在于"复杂照片（人像/宠物）的身份特征保留"，测试集应包含若干宠物/人像样本，主观评估生成结果是否"看起来还是原来的样子"，而非仅验证像素化本身是否正确。
