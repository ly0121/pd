# 图纸生成逐格一致提速设计

日期：2026-11-10

## 目标

在当前提交 `5c87f29` 的基础上缩短生成图纸等待时间，同时保持相同图片、调色板、生成选项、运行环境与相同随机哈希种子下的最终网格色号（包括 EMPTY/H1）逐格一致。既有调色板缓存、轮廓、Vision 显著性、噪点清理、渐变与透明连通规则均保留；不重启此前失败的区域色块合并实验。

## 第一阶段：分格迭代中消除重复计算

- 使用现有基准中的 48/100/150 格与受控哈希黄金图记录当前结果。`SuperpixelSegmenter.refine` 中候选集合顺序、距离公式、逐项比较的 `<` 平局规则及乘加顺序必须维持；只把与候选格无关的正数系数（例如同一像素的 `pow(effectiveCompactness / spatialScale, 2)`）提取到候选循环外。
- 对等距平局、非方格、显著性非均匀权重、alpha/H1、不同调色板分别做标签和最终色号对照。若任何非噪声导致的标签或色号不同，恢复旧计算顺序，缩小优化范围。分别记录优化前后五次中位数与波动，若收益不高于噪声则不保留复杂改动。

## 第二阶段：不透明图像 alpha 快速路径

- `SourceAlphaCells.classify(source:)` 目前先解整幅 CGImage 为 RGBA，再复制 alpha、分配连通数组与容量为每个像素的 Int 队列，即使图片完全不透明亦如此；对高像素照片可能造成显著临时内存与卡顿。先测 opaque 与透明环/封闭孔洞图在 48/100/150 格不同源分辨率的时间与峰值内存。
- 若解码后的 RGBA alpha 全为 255，可立即返回全 nil 的固定格数组，不分配 alpha 数组、连通数组与队列；若存在任何 alpha <255，继续完全相同的旧分类逻辑（阈值 ≤127、四邻接及半格覆盖）。CGImage alpha 缺失/带 alpha 但实际 opaque、RGBA 数据转换失败等情况逐一核对，不能仅靠 CGImage 像素格式断定内容不透明。仅在确证结果相同且有实际内存/耗时收益时保留。

## 验收

测试必须先失败再实现。每个阶段跑 `SWIFT_DETERMINISTIC_HASHING=1 swift test --package-path BeadCore`（含黄金网格）、BeadPersistence、iOS 模拟器真实 App 新建/尺寸重生 UI 测试；在独立纯函数层直接比较旧／新 refine 标签和 alpha 分类，包括强制平局。基准每组预热一次、至少五次测中位数，明确 Mac 与 iOS 真机的适用边界。不更改源图像采样比例/迭代数/颜色差公式，不提交或推送直到用户要求。
