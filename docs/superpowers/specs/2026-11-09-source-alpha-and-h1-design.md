# 原图透明区域与 H1 豆色图纸设计

日期：2026-11-09

## 目的与约束

对导入的带 alpha 图像保留「外侧透明＝不放豆」和「主体内部透明孔洞＝H1 豆」两种不同语义；当前所选色表无 H1 时内部孔洞也不放豆。原图透明区域在新建和调整尺寸重新生成时均生效，不受「去除背景」开关约束；现有 Vision 主体识别只用于额外剔除不透明背景。现有图纸编码 `EMPTY`、MARD H1 色值、库存色号及旧项目数据格式不变。PNG 相册保存沿用现有对 `.empty` 图纸的透明导出路径。

## 定义与判定

- `MardColor.empty` / `EMPTY` 表示格子里不放豆，不显示色号、不计入用量；编辑画布白底可见，导出原图及保存到相册的 PNG 在格中心透明。H1 是内置 MARD 色号（现有视觉色值 `FDFBFF`），是需要放的豆：有可见浅色填充，放大编辑／导出显示 H1，计入用量。绝不把 `.empty` 重命名成 H1，也不把 H1 画成透明像素。
- 在裁切或按内容适配选定实际用于生成的原图之后、缩图之前，提取 alpha；把 alpha ≤ 0.5（8 位 ≤ 127）的像素视作透明种子。对这些种子进行**四邻接**连通遍历：能从实际图像边缘到达的是「外侧」；其他种子是「内部孔洞」。原图完全不透明时无固定透明分类，保持原有行为。若透明像素通过至少一个边缘种子与外侧相连，则整个连通域都是外侧而不是孔洞。
- 缩图时 RGB 和透明分类使用与生成图像**相同的最终像素坐标系**；避免把原图缩图后的半透明边缘当作新孔洞。每个目标豆格按原图几何区域统计外侧种子、内部种子与不透明像素的覆盖：仅当其中某一透明类别覆盖该格**至少一半**时，将其固定为相应类别；其余混合格由原有算法匹配 RGB。边缘混合格不因极少量透明像素变成孔洞或漏豆。统计基于格子等分的几何坐标，不依赖 SLIC 后续移动的像素标签，确保外轮廓位置稳定。非正方形长宽比和非整倍数缩放必须正确映射。
- 外侧固定格 → `.empty`；内部固定格 → 若**本次生成调色板**含 H1 则用目录中的真实 H1，否则 `.empty`。这条规则在 `NoiseCleaner` 与 `GradientOrderEnforcer` 后仍有效：从固定格掩码最后应用覆盖并保护，不允许去噪或渐变修正改变它。常规不透明格照原算法选择颜色，H1 仅在本次选用的调色板含 H1 时作为普通候选参与匹配，不另设“看起来透明”的启发式强制规则；其与近白色（如 H2）的选择仍由现有颜色距离算法决定。

## 流程与边界

- 新建：选择正方形裁切或适应内容图像 → 在此图像提取 alpha 连通分类 → 准备缩图 RGB 和目标格覆盖掩码 → 现有重要性图、轮廓、颜色优化与可选 Vision 背景去除 → 在最终网格上强制固定透明格 → 保存原图与网格。
- 去除背景关闭：只根据原图 alpha 形成固定格，其余按原图配色；开启：Vision 可将额外的**非固定格**设为 `.empty`，但无法把固定 H1 孔洞改为空格，也无法给固定外圈上色。若 Vision 无识别结果，仍保留 alpha 分类。
- 调整尺寸重新生成：以项目保存的用于生成的原图，在用户确认时读取最新「我的颜色」完整库存（无论旧图最初选择哪个预设）；按同一 alpha 规则重建目标格掩码；若库存为空仍沿用当前阻止生成逻辑。旧项目的原图若没有 alpha，行为与现有尺寸重新生成一致。
- 导出与缩略图：有 `.empty` 时相册写 PNG 保留透明；H1 格按已存在的普通色号渲染。列表缩略图目前将 `.empty` 绘成浅白色，本任务不改动列表渲染；不会错误地把 H1 从用量中排除。无 `.empty` 的相册保存方式不变。

## 可验证场景

1. 合成 RGBA 图：透明外圈、实色主体与完全封闭的透明孔洞；开／关「去除背景」均得到外圈 `EMPTY`、有 H1 库存时内部 H1、无 H1 时内部 `EMPTY`。
2. 洞通过仅对角线与外圈相触时按四邻接仍视为内部；洞通过上下左右路径连到边缘时变成外圈。阈值两侧的 alpha 及 50% 格覆盖边界有确定结果。
3. 小孔洞与细边框不会被噪点清理重上色；弱透明边缘低于半格时继续按普通颜色匹配；无 alpha 的图片、非正方形图片、不同缩放分辨率保持旧生成流程和尺寸正确。
4. 若当前色表含 H1，不透明浅色格在原有颜色匹配判断认为 H1 更近时可出现 H1；不在色表时不会由透明孔洞产生 H1。固定 H1 出现在编辑页、导出色号和用量中，`.empty` 不计用量。
5. 在 iOS 模拟器以 RGBA 样图走新建和调整尺寸流程，确认相册中有 `.empty` 的 PNG 保存为 RGBA、透明格中心 alpha 为 0、穿过透明格的每 5 格实线保留；完整 BeadCore / BeadPersistence / iOS UI 测试仍通过。
